# GenAug — GenAug: Retargeting Behaviors to Unseen Situations via Generative Augmentation (2023, arXiv 2302.06671)
Setup: real xArm5 with SUCTION gripper, end-effector control; one RealSense D435i RGB-D on tripod (projected to top-down view); policy = CLIPort (Transporter-style pick/place affordance map, language-conditioned), NOT a closed-loop visuomotor policy. 10 tasks × 10 demos each, all collected in ONE demo environment by clicking pick/place points on a top-down image (not teleop). Augmentation: each demo augmented 100× → 1000 augmented samples per task; ~30 s per scene for all augmentations. Object masks labelled MANUALLY; needs calibrated camera + 40 object meshes (GoogleScan/Free3D). Sim: 5 "pack X" tasks, 1/10/100 demos, RGB only.
Method: depth-guided Stable Diffusion (text + depth) to (1) re-texture the pick object/receptacle in-category (random colour/material prompts), (2) swap category by rendering a random mesh at the object location then texturing it, (3) add mesh-rendered distractors with bbox collision check, (4) re-generate background/table with prompts ("a view inside a kitchen"). Actions unchanged.
Claim: generative scene augmentation from 10 demos in one scene lets the policy work in unseen environments and on unseen objects.
Evidence:
 - Real, GenAug only (Table I, 10 tasks, 10 test scenes each): unseen environment 85% avg, unseen place object 52%, unseen pick object 45%. Per task ranges 0.5–1.0 env, 0.3–1.0 place, 0.0–0.7 pick.
 - Real, with vs without GenAug (Table II, 5 scenes each, evaluated OFFLINE by comparing predicted affordance to ground-truth location, not by robot execution): unseen env 38% → 80%, unseen place 8% → 54%, unseen pick 10% → 46%.
 - Sim (Table III, 5 tasks, 1/10/100 demos, TransporterNet and CLIPort): table text is garbled in extraction; authors state GenAug beats no-aug, spatial aug, random copy-paste (LVIS), random background (LVIS), random distractors and R3M fine-tune in most cells; random copy-paste / random background "provide reasonable robustness in unseen environments" but fall short on unseen OBJECTS. Best-guess parse of the unseen-env block's last rows (GenAug / GenAug w depth): TransporterNet 43.9/58.5/77.6 and 47.8/83.8/91.2 at 1/10/100 demos — treat as uncertain.
Ablations:
 - Number of augmentations per demo 0/10/50/100 (sim, 1 task, 100 test scenes): monotone improvement — figure only, qualitative.
 - Depth-guided diffusion + mesh vs plain inpainting: inpainting "often does not result in reasonable visual augmentation" — figure only, qualitative.
Failure/limitations: authors: actions are not augmented (assumes same trajectory valid, no collision with added objects); no temporal consistency across video frames (frame-by-frame generation) → only suits single-frame policies; ~30 s per scene; failures when background colour ≈ object colour or bright distractors. Critical read: (a) the real "with vs without" comparison is an offline affordance-match metric on 5 scenes/task, not robot rollouts; (b) suction + top-down pick makes cross-category swaps action-invariant — NOT true for a parallel gripper where object shape changes the grasp; (c) CLIPort's spatial action map is equivariant and very sample-efficient, results do not transfer directly to a closed-loop chunked policy on joint space; (d) no lighting or camera-pose shift tested; (e) 10 demos, tiny eval counts.
Conflicts: GreenScreenAug (real, 8.2k rollouts, ACT) finds generative aug (GenAug/ROSIE-style) ~21% WORSE than chroma-key random textures for scene generalisation; RoboEngine likewise finds simple texture/ImageNet backgrounds strong and fast. GenAug's own sim table concedes random background is competitive for unseen ENVIRONMENTS; generation only clearly wins for unseen OBJECT appearance. Consistent picture: cheap random backgrounds for scene shift; generative object re-texturing is the only thing that attacks "different-looking pumpkin".
Relevance: MEDIUM-LOW as a method, MEDIUM as evidence. Our problem includes "different-looking pumpkin" — in-category re-texturing via mask + depth-guided diffusion is the one augmentation that directly targets that, but frame-wise generation flickers across a trajectory and a wrist camera would need consistent masks for every frame; 30 s/frame × ~100 demos × hundreds of frames is infeasible on an 8 GB laptop. A cheaper proxy: per-episode consistent hue/texture shift applied only inside the object mask (SAM2-tracked), or simply collect with 3–5 physically different pumpkins.
Decision impact:
 - Q05 augmentation: generative object re-texturing — weakly SUPPORTED for novel object appearance, not for scene shift — confidence L (CLIPort/suction, offline metric, 10 demos).
 - Q05 augmentation: random background replacement suffices for unseen environments — SUPPORTED (authors' own baseline) — confidence L/M.
 - Q14 robustness: object-appearance shift is the hardest axis (pick 45% vs env 85% even with GenAug) — SUPPORTED — confidence M → collect physical object variety.
