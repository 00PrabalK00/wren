# 3DDiffuserActor — 3D Diffuser Actor: Policy Diffusion with 3D Scene Representations (2024, arXiv 2402.10885)
Setup: Sim: RLBench multi-view (18 tasks, 4 calibrated RGB-D cams incl. wrist) and single-view (10 tasks, front cam only; GNFactor split), CALVIN ABC→D (34 tasks, 24h play data, trained on language-annotated subset). Real: Franka + ONE front Azure Kinect (ToF RGB-D), 1280×720 → 256×256, 12 tasks, 15 demos/task, 10 trials/task. Actions: end-effector keyposes (RLBench, + BiRRT motion planner) or keypose-segmented trajectories (CALVIN), 6D rotation, binary gripper. Fusion: pretrained CLIP-ResNet50 2D feature map → each patch lifted to 3D with averaged depth + intrinsics + EXTRINSICS → 3D scene tokens (feature + xyz); noisy trajectory tokens and proprio also carry xyz; relative-3D (rotary) attention among 3D tokens, cross-attn to CLIP language tokens. Diffusion, L1 noise loss, separate schedulers for position (scaled-linear) and rotation (squared-cosine). Runtime on 2080 Ti (CALVIN): 600 ms per 6-pose trajectory (~10 Hz effective).
Claim: tokenized 3D scene features (lifted pretrained 2D features) + action diffusion + translation-equivariant relative 3D attention beat 2D diffusion policies and prior 3D policies (incl. DP3) by large margins.
Evidence:
 - RLBench multi-view avg success: C2F-ARM-BC 20.1, PerAct 49.4, HiveFormer 45, PolarNet 46, RVT 62.9, Act3D 63.2, 3DDA 81.3 (same keyposes for all).
 - RLBench single-view (front RGB-D only): GNFactor 31.7, Act3D 65.3, 3DDA 78.4.
 - CALVIN ABC→D avg len: DP3 (1D pooled point embedding, retrained by authors) 0.31, RT-1 0.90, ChainedDiffuser 0.84, RoboFlamingo 2.48, SuSIE 2.69, GR-1 3.06, 3DDA 3.35.
 - Real (15 demos/task, 10 trials): per task 100,100,50,30,80,100,90,90,50,20,40,90 (close box/put duck/insert peg hole/insert peg torus/…/stack blocks 20/stack cups 40); mean ≈70% (my average). Demos contain multiple modes (pick one of two ducks etc.).
 - Runtime: 3DDA 600 ms, DP3 581 ms, ChainedDiffuser 1170 ms on 2080 Ti.
Ablations:
 - 3D scene tokens → 2D (per-view avg-pooled features, = their 2D Diffusion Policy): 81.3 → 47.0 (RLBench multi-view).
 - relative 3D attention → absolute attention: 81.3 → 71.3.
 - Depth noise (App. A.1, single-view, 10 tasks, trained on CLEAN depth): Gaussian noise σ²=0.01 on each pixel's 3D location → 72.4 (−6.0); σ²=0.03 → 50.1 (−28.3). 3 seeds × 25 episodes/task.
 - Separate noise schedulers for rotation matter (App. B.7, qualitative/figure).
 - CALVIN: model overfits → higher weight decay / fewer epochs (App. B.5).
Failure/limitations: authors: requires camera calibration + depth (all 3D policies); quasi-static tasks only; slower than non-diffusion policies. Failure analysis (App. A.2): imprecise pose prediction and language confusion dominate on RLBench. Critical read: RLBench numbers rely on keypose extraction + motion planner (not closed-loop dense control like ours); real eval 10 trials/task, no OOD real tests; noise test is additive isotropic Gaussian on clean sim depth (not stereo-depth artifacts: holes, flying pixels, edge bleeding); DP3 on CALVIN was retrained by these authors with a crude setup (bounding-box point sampling, horizon 4) — its 0.31 is likely under-tuned.
Conflicts: disagrees with DP3/iDP3's "tiny pooled point encoder is enough" — here a holistic pooled 3D embedding (DP3) fails badly on CALVIN, which is multi-task, language-conditioned, cluttered, and scene-shifted (ABC→D); tokenized per-patch 3D features localize scene changes. Agrees with iDP3/DP3 that 3D > 2D (47.0 vs 81.3 within the same model family). Uses pretrained 2D features (CLIP) lifted into 3D rather than color-free XYZ — so appearance invariance is NOT the mechanism here; geometry-grounded attention is.
Relevance: Most useful as the "how to fuse RGB with depth" recipe: lift pretrained 2D patch features to 3D with depth and do relative-position attention — keeps semantics (pumpkin vs tray) AND geometry. Needs RealSense extrinsics (hand–eye/checkerboard calibration once; fixed scene cam makes this feasible; could also use camera frame since camera is fixed, but then camera shift breaks it). Wrist cam can be added only with per-frame FK-based extrinsics (SO-101 backlash makes that noisy). Model (CLIP-RN50 + transformer) should fit 8 GB, but diffusion at 600 ms/trajectory on a 2080 Ti is slow; would need DDIM/few-step. Keypose formulation does not suit our dense joint-space teleop data. Noise ablation: moderate 3D noise costs ~6 pts, heavy noise ~28 pts → stereo D4xx noise at 0.3–0.6 m is probably in the "mild" regime for a large pumpkin but not for thin gripper parts.
Decision impact:
 - Q04 3D vs RGB: supports 3D (tokenized, RGB features lifted to 3D) over 2D — H in sim (81.3 vs 47.0 controlled ablation), L real (no 2D baseline in real).
 - Q04 fusion design: supports "lift pretrained 2D features to 3D points + relative attention" over pooled color-free point embedding for multi-task/cluttered scenes — M (CALVIN DP3 comparison possibly under-tuned).
 - Q04 depth-noise sensitivity: trained-on-clean model loses 6 pts at σ²=0.01, 28 pts at σ²=0.03 — M (sim Gaussian noise only; consider training with depth-noise augmentation).
 - Q01 action head: diffusion > regression/classification 3D policies (Act3D 65.3 vs 78.4 single-view with similar tokenization) — M (confounded by other differences).
 - Q10 latency: 600 ms per trajectory prediction on 2080 Ti — M (needs fewer denoise steps for our 8 GB laptop).
 - Q11 cameras: single front RGB-D view achieves 78.4 vs 81.3 with 4 views — M (sim).
