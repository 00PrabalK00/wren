# PointVLA — PointVLA: Injecting the 3D World into Vision-Language-Action Models (2025, arXiv 2503.07511)
Setup: Base = DexVLA (Qwen2-VL 2B VLM + 1B ScaleDP diffusion-transformer action expert, 32 blocks), Stage-1 pretrained weights. Real: (a) bimanual UR5e, 3 cams (2 wrist D435i RGB + 1 top RealSense L515 for point cloud), 15 Hz, long-horizon conveyor packing, 11 trials; (b) bimanual AgileX, 3 cams (2 wrist D435i + base; L515 for point cloud), 30 Hz, 4 tasks × 20 demos (80 total), multi-task. Chunk size 50. Sim: RoboTwin (v1), 20 and 50 demos, 3 seeds × 100 evals, 320×180 images. Fusion: VLM sees only 2D images + text (VLM trainable); point cloud → scratch hierarchical conv encoder (iDP3-like, max-pool between layers, multi-level concat, 128-dim) → zero-init linear 128→1280 → adapter MLP + ADDITIVE injection into 5 selected action-expert blocks (the later blocks, chosen by skip-block analysis); original action expert frozen except final layers.
Claim: point clouds can be added to a pretrained 2D VLA as a side conditioning signal without retraining, improving few-shot learning and giving 3D-only abilities (real-vs-photo discrimination, table-height generalization).
Evidence:
 - Long-horizon packing on moving conveyor (UR5e, 11 trials; Avg. Len.): Octo 0.27, OpenVLA 0.36, DP 0.36, ScaleDP-1B 0.72, DexVLA 1.72, PointVLA 2.36.
 - Few-shot multi-task (AgileX, 20 demos/task): figure only, qualitative: PointVLA ≥ DexVLA on all 4 tasks, DP near zero, ScaleDP-1B not much better than DP.
 - Real-vs-photo (detergent replaced by photo on screen): OpenVLA/DP/ScaleDP-1B/DexVLA 0/3 (DexVLA loops trying to grasp), PointVLA 3/3 correctly ignore.
 - Table height 3 mm (train) → 52 mm (test), place-bread: all 2D baselines 0/5 (push down to training height), PointVLA 5/5.
 - RoboTwin (my mean over the 13 parsed task rows; order DP3-PC / DP3-PC+RGB / DP / PointVLA): 20 demos 23.6 / 15.6 / 1.9 / 28.6; 50 demos 37.0 / 31.6 / 9.6 / 44.6. Block Hammer Beat: 20 demos 47.7 / 44.7 / 0.0 / 61.2; 50 demos 58.3 / 79.0 / 0.0 / 84.6.
Ablations:
 - Skip-block analysis on DexVLA shirt folding (figure only): skipping any of first ~11 blocks breaks the policy; single blocks after 11 skippable; up to 5 consecutive later blocks skippable, 6 → failure → inject 3D into 5 blocks.
 - Adding RGB to DP3 (RoboTwin baseline, implemented by RoboTwin): lowers success in 12/13 task rows at 20 demos and 7/13 at 50 demos (my count) — naive concatenation of RGB with points hurts in low data.
 - Pretrained 3D encoders "hindered performance" (stated, no numbers) → scratch conv encoder.
Failure/limitations: no limitations section. Critical read: tiny trial counts (3, 5, 11); real-vs-photo and height tests are single-task demonstrations of a mechanism, not statistics; RoboTwin baselines copied from RoboTwin paper while PointVLA trained by authors (different pipeline; DP at 320×180 near-zero is suspicious); 3B-parameter model vs 255M DP3 — confounds scale, pretraining, and 3D; no ablation of "DexVLA + point cloud via other fusion" (e.g., tokens into VLM) with numbers; calibration/cropping of the L515 cloud not described.
Conflicts: agrees with DP3/iDP3 (scratch small point encoder > pretrained 3D encoder). Agrees with PointVLA's own RoboTwin DP3+RGB result and DP3 paper (color adds nothing / hurts) — but 3DDiffuserActor shows RGB-derived features lifted to 3D help; difference is HOW RGB is fused (naive per-point color concat vs pretrained semantic features vs separate 2D branch). Height result mirrors DP3/iDP3 spatial generalization claims.
Relevance: Gives a concrete fusion pattern for our "2D pretrained policy + depth" question: keep the pretrained RGB pathway (SmolVLA/any VLA or pretrained image encoder) intact and ADD a small scratch point-cloud encoder via zero-init linear layers into late action-head blocks — preserves pretrained 2D behavior at init, trains cheaply. With SmolVLA's action expert we could inject into a subset of expert layers. Our fixed scene RealSense (stereo D4xx, not L515 LiDAR) would supply the cloud; wrist stays RGB. But the 3B base doesn't fit our 8 GB inference well; the idea transfers, the model does not. Height/pose shift of the tray or pumpkin is exactly what 2D policies miss.
Decision impact:
 - Q04 fusion: supports "separate scratch point encoder, zero-init additive injection into action head, 2D VLM untouched" — M (mechanism plausible, tiny real trials).
 - Q04 3D vs RGB: 3D adds height generalization (0/5 → 5/5) and real-vs-photo discrimination (0/3 → 3/3) that RGB-only VLAs lack — L/M (few trials, single tasks).
 - Q04 RGB+points naive concat: DP3+RGB worse than DP3 in 12/13 tasks at 20 demos — M (RoboTwin-reported baselines).
 - Q04 encoder: pretrained 3D encoders hurt; small scratch conv encoder (128-d) — L (stated, no numbers).
 - Q13 data: 20 demos/task sufficient for a pretrained VLA + 3D to do simple tasks — L.
