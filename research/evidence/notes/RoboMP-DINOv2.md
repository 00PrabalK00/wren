# RoboMP-DINOv2 — RoboMP-DINOv2: Prompts, Not Filters for Robust Robot Manipulation (2026, arXiv 2609.25506)
Setup: SIM ONLY. 7 settings (Place Cube, Put Can clear, Put Can with obstacle, Pull Tool, Peg Insertion, Long Horizon, Two-Arm stacking), 100 demos/task collected in clean scenes; Diffusion Policy head; frozen CLIP text encoder for language; observation history To. Encoder: DINOv2 ViT-B/14 at 112×112 input (8×8 patch grid) → 1×1 conv to d=256 + learned 2D pos-emb + learned per-mask-slot prompt embeddings ADDED at mask locations → 3-layer transformer → mean pool; the DINOv2 backbone is FINE-TUNED jointly (all DINOv2 baselines are fine-tuned too). Masks: simulator GT at training, Grounding-DINO + SAM at test. MCR = paint the masked object regions with one random uniform color during training. Fig. 2 variants use 3 seeds × 50 initial conditions; per-cell trial counts are not otherwise stated.
Claim: using masks as additive prompts on full-scene DINOv2 features (not as filters) improves robustness to spatial shift and clutter; randomizing color only inside object masks (MCR) generalizes to unseen object colors while keeping context cues.
Evidence (Table 1, macro-average over 7 settings):
 - Clean spatial OOD (held-out positions): 2D object-centric masking 8.1; 3D object-centric (GROOT-style) 28.6; DP–DINOv2 (fine-tuned) 50.7; RoboGround–DINOv2 (masks concatenated to RGB) 55.9; RoboMP 60.7.
 - Clutter OOD: 2D obj 6.3; 3D obj 16.4; DP–DINOv2 41.0; RoboGround 36.8; RoboMP 59.7. Put-can-with-obstacle: RoboMP 80 vs DP–DINOv2 52 vs 3D-obj 3. Two-arm: 81 vs 41.
 - The 3D object-centric method wins Place Cube spatial (85 vs RoboMP 54) but collapses when context matters (obstacle 7, two-arm 12).
 - Appearance OOD (unseen object colors; Table 3, all trained with color randomization): DP–DINOv2 + full-image color randomization 19.1; 2D obj 12.0; 3D obj 14.2; RoboGround + masked rand 35.1; RoboMP-MCR 72.5 (e.g. Pull Tool 82 vs 10; Peg 70 vs 25; Long horizon 90.6 vs 49.8).
 - Appearance + clutter (Table 4): text reports DP full-image rand 0.01, DP + masked-region rand (no mask input) 0.11, RoboGround 0.07, 2D obj 0.00, RoboMP-MCR 0.20 (the extracted table columns do not match the text exactly — treat as approximate).
 - Context-dependent color cue (stove light decides action): RoboMP-MCR 88% / 71% (green / red) vs DP–DINOv2 with full-image color randomization 25% / 19% — full-image color jitter destroys decision-relevant color.
 - Representation sensitivity (Table 2): under recoloring, RoboMP-MCR reduces relative-L2 feature change vs un-augmented DP–DINOv2 by 5.5–92.9× across tasks; under clutter it is lower on 4/5 tasks.
Ablations (Fig. 2, clutter, 3 tasks; figure only): full RoboMP > all-one masks (prompt without localization) > / ≈ no prompt > DINOv2 CLS+mean readout.
Failure/limitations: authors: evaluations are system-level; component effects are not causal. My read: simulation only; GT masks in training but GroundingDINO+SAM at test (large inference latency, not reported); 112×112 input; a fine-tuned DINOv2 ViT-B baseline already loses ~10 pts from clutter; the appearance shift is flat unseen colors, simpler than real texture/lighting; no lighting or camera shift; 2026 preprint, no independent replication.
Conflicts: consistent with iDP3/Burns in that a fine-tuned 2D image encoder (here DINOv2) is fragile to appearance shift (19% with standard color randomization). Agrees with GreenScreenAug/RoboEngine that the SPATIAL SUPPORT of augmentation matters (object-region/background-region randomization > global jitter). Partly counters DP3/GROOT-style object-centric 3D: hard filtering removes needed context (obstacle 3–7%). Suggests fine-tuned DINOv2 is a workable baseline but not robust by itself.
Relevance: our pumpkin appearance shift maps to MCR: we can get pumpkin masks cheaply (SAM2/GroundingDINO offline on training frames only) and randomize pumpkin color/texture during training. That keeps inference cost at zero if we only use MCR as augmentation (Table 4 suggests masked-region randomization helps even without mask inputs: 0.01 → 0.11). Mask-prompting at inference needs a segmenter at runtime (latency on the laptop) — probably not worth it for one pumpkin + tray.
Decision impact:
 - Q05 augmentation: object-region color randomization (from offline masks) >> full-image color randomization for unseen object appearance (72.5 vs 19.1 system-level; 0.11 vs 0.01 aug-only) — supports masked-region aug — M (sim only, but large gaps).
 - Q05 augmentation: global color jitter can erase decision-relevant color cues (25% vs 88%) — caution on strong global hue jitter when color matters — M.
 - Q03 vision: fine-tuned DINOv2 ViT-B + DP is a reasonable but shift-fragile baseline (clutter 50.7→41.0 macro) — ~ DINOv2 fine-tuned — M.
 - Q03 vision: spatial patch tokens + small transformer > CLS+mean readout — supports spatial readout — L/M (figure only).
 - Q04 3D: hard object-centric 3D filtering fails when context matters (obstacle 3%) — against pure segmented point clouds; keep full-scene context — M.
 - Q14 robustness: clutter and appearance shift both need explicit handling beyond a pretrained encoder — supported — M.
