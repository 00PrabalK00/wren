# RoboVLMs-WhatMatters — What Matters in Building Vision-Language-Action Models (2024/2026 v4, arXiv 2412.14058)
Setup: >600 experiments, 8 VLM backbones (Flamingo 3B/4B/9B, LLaVA, Qwen-VL, MoonDream, UForm, KosMos-2, PaliGemma-3B), 4 formulations (one-step discrete, one-step continuous, interleaved history, policy-head history). Benchmarks: CALVIN (34 tasks, 24k demos; ABCD→D and ABC→D zero-shot scene), SimplerEnv (Google Robot, WidowX/Bridge), real Kinova Gen3 + Robotiq, static Kinect Azure + wrist D435i (RGB only), 105-task/74k-trajectory dataset, eval 20 tasks × 5 settings (simple, novel verb, unseen distractor, unseen object, unseen background) × 3 rollouts. Actions: 7-D EE pose (+ gripper). CALVIN models trained fixed 5 epochs, final checkpoint; best config: KosMos-2, history window 16, chunk 10, side+wrist. Compute: 4×8 A100-80G.
Claim: build VLAs from VLMs with strong VL pretraining, continuous actions, multi-frame history fused in a separate policy head; cross-embodiment data helps only as pretraining followed by in-domain post-training; in-domain data beats cross-embodiment data.
Evidence:
 - Formulation (Table I, CALVIN ABCD→D Avg. Len; chunk 10, execute first step): KosMos: one-step discrete 0.55, one-step continuous 4.09, interleaved 4.12, policy head 4.49. PaliGemma: 0.44 / 4.04 / 4.25 / 4.42. Flamingo: 1.22 / 1.30 / – / 4.09. LLaVA (perceiver-resampled): 1.85 / 2.37 / 2.44 / 2.71.
 - Backbone (Ext. Table 5; single side view, policy head, 5 epochs ABCD): Qwen-VL 9B 0.30, Flamingo 3B 1.57 / 4B 1.71 / 9B 1.83, MoonDream 1.81, UForm (1.3B) 2.28, KosMos-2 (~2B, 90M VL pairs) 3.59, PaliGemma-3B (10B pairs) 3.82. Size is not the driver: 9B Qwen-VL and Flamingo-9B lose to 2–3B KosMos/PaliGemma; LLaVA/Qwen needed a perceiver resampler to reduce vision tokens to be usable.
 - VL pretraining vs none (Supp. Table 2, Avg. Len): KosMos P.H. ABCD 4.49 vs 2.51 (no VL); ABC→D 4.25 vs 0.56; 5x data 4.51 vs 3.32. KosMos interleaved ABCD 4.12 vs 1.38; ABC→D 2.70 vs 0.65. Flamingo-9B P.H. 3.97 vs 1.69.
 - Data efficiency (Ext. Table 4, Avg. Len at 0.1x / 1x / 5x ABCD): Flamingo P.H. 3B 0.13 / 4.09 / 4.21; 4B 0.55 / 3.79; 9B 0.83 / 3.97; KosMos interleaved 2.49 / 4.12 / 4.46; KosMos P.H. 2.52 / 4.49 / 4.51.
 - Best model CALVIN ABC→D 4.25 vs GR-1 3.06 (prev. SOTA, +1.19 tasks). Real robot: KosMos P.H. > OpenVLA, Octo-Base in all 5 settings, esp. simple and unseen background (figure only, qualitative).
 - Action objective × execution (PaliGemma one-step-continuous, Table IIa, Avg. Len): ABC→D: FM chunk 3.68 / first 2.45 / ensemble 3.14; MSE+BCE chunk 3.57 / first 2.19 / ensemble 3.14. ABCD: FM 4.09 / 3.56 / 4.12; MSE+BCE 4.04 / 3.06 / 3.94.
 - MoE action expert (π0-style, Table IIb): ABC→D MSE 3.57 → 3.69, FM 3.68 → 3.84 (helps unseen scene); ABCD MSE 4.04 → 3.46, FM 4.10 → 3.84 (hurts seen).
 - Cross-embodiment (figure only for exact numbers): OXE co-training alone ≈ no gain; post-training (OXE co-train then in-domain finetune) Bridge 50% vs finetune-only 44%; Google Robot: same-robot other-task data (RT Finetune) > OXE; CALVIN few-shot (10 traj/task): OXE pretraining +17.2% single-task SR and +0.25 Avg. Len.
Ablations: all of the above are controlled ablations (same data, same epochs, final checkpoint). History length: "increasing observable history can enhance performance at higher compute" (no table extracted).
Failure/limitations: authors: action tokenizers (VQ, FAST) and objectives underexplored; limited backbone set; real-time deployment of large models remains hard. Critical read: CALVIN-centric (sim, 24k demos — far more data than ours); final-checkpoint 5-epoch protocol may disadvantage slower-converging configs; real eval is 3 rollouts per setting; discrete baseline is RT-2-style binning (not FAST); "one-step" continuous executes only the first action of a 10-chunk in Table I, which Table IIa shows is the WORST execution mode — so Table I underestimates one-step models relative to history models.
Conflicts: agrees with LBM (in-domain > cross-embodiment; pretraining helps few-shot). Agrees with Hyper-DP3/ACT-family evidence that MSE regression ≈ diffusion/flow when chunks are executed (FM only +0.1 Avg. Len). Disagrees mildly with copycat/causal-confusion literature (history hurting): here history consistently helps — because CALVIN is partially observable long-horizon and data is plentiful (24k demos); with 50–100 demos history can still cause copycat issues. Execution-mode finding (chunk > ensemble > first on unseen scenes) partially conflicts with ACT's temporal-ensembling preference.
Relevance: For our SmolVLA-class choice: (1) backbone VL-pretraining quality matters more than size — a 2–3B well-pretrained VLM beats 9B ones; SmolVLA (~450M, SmolVLM2) is below the studied range, so no direct evidence for it. (2) Without VL pretraining, unseen-scene generalization collapses (4.25 → 0.56) — relevant to our new-lighting/new-scene failures: keep the pretrained vision-language features. (3) Policy head with history (window 16) was best — but on our 8 GB laptop a 16-frame VLM pass is expensive; policy-head design only runs the VLM once per frame and caches, which is feasible. (4) Chunk execution > first-action or ensembling in unseen scenes; our chunk-boundary jerk should be solved by smoothing/RTC, not by switching to first-action execution. (5) MoE/action expert (SmolVLA/π0 style) helps unseen scenes but hurts in-distribution fit.
Decision impact:
 - Q03 vision/backbone: strong VL pretraining essential (ABC→D 4.25 vs 0.56 without) and matters more than size (PaliGemma-3B 3.82 > Qwen-VL-9B 0.30) — H (controlled, CALVIN).
 - Q01 action head: continuous >> discrete binning (KosMos 4.09 vs 0.55); flow matching ≈ MSE+BCE (3.68 vs 3.57 ABC) — H for discrete-binning penalty, M/H for FM≈MSE.
 - Q07 history: multi-frame history via policy head > one-step (KosMos 4.49 vs 4.09) and > interleaved (4.12) — M (confounded by first-action execution; large-data sim).
 - Q06/Q10 execution: execute full chunk > ensemble > first action on unseen scenes (FM 3.68 / 3.14 / 2.45) — M/H.
 - Q12 model size: bigger VLMs more data-efficient within a family (Flamingo 0.1x: 3B 0.13, 9B 0.83) but family/pretraining dominates size — M.
 - Q13 data: in-domain same-robot data > cross-embodiment; cross-embodiment only helps via pretrain→post-train (+6 pts Bridge) and few-shot (+17.2% SR) — M.
 - Q14 robustness: MoE/action-expert separation improves unseen-scene generalization (+0.12–0.16 Avg. Len) at cost of seen-scene fit — M.
