# DemoGen — DemoGen: Synthetic Demonstration Generation for Data-Efficient Visuomotor Policy Learning (2025, arXiv 2502.16932)
Setup: policy = DP3 (point cloud + proprio, diffusion), trained 2M obs-action pairs fixed regardless of dataset size, AdamW 1e-4. Real: Franka + Panda gripper (3 tasks) or Allegro hand (4 tasks), single RealSense L515, point cloud cropped, DBSCAN, FPS to 1024 pts, 10 Hz, To=2, Tp=8, Ta=5 (0.5 s replanning); plus Galaxea R1 bimanual humanoid (1 task, head cam). Sim: 8 MetaWorld tasks with ENLARGED randomisation. Absolute EE pose actions with IK controller. Source data: ONE human teleop demo per task, replayed twice to capture 3 point-cloud trajectories (sensor noise variety). Generated: 3 × #eval configs × 9 (±1.5 cm perturbations) = 72–432 demos per task. Eval: 530 real rollouts total, 5 reps per config.
Method: segment objects on first frame (Grounded SAM) → parse trajectory into motion (free-space) and skill (contact) segments by EE-object distance → for new object pose, transform skill segments rigidly with the object and re-plan motion segments (motion planner) → synthesise point clouds by transforming object/EE point segments. ~22 s CPU for a whole dataset vs 83.7 h estimated for MimicGen-style robot replay.
Claim: spatial generalisation of visuomotor policies comes only from demonstrated object configurations; synthetic spatial re-targeting of 1 demo recovers most of it.
Evidence:
 - Empirical study (sim Precise-Peg-Insertion, 1 cm tolerance, 40×40 cm config space, success % at 25/50/75/100/150/200/300/400 demos, 3 seeds): DP scratch 1/8/18/22/38/44/56/44; DP+R3M 0/2/9/9/16/17/17/21; DP+DINOv2 4/17/50/61/79/83/89/92; DP+CLIP 2/8/39/53/78/89/94/96; DP3 3/11/29/49/86/92/96/98; DP3 half workspace 17/49/66/91/96/100/100/100; DP3 fixed positions 100 at all counts.
 - Button task (441 eval placements): effective range ≈ union of neighbourhoods of demonstrated placements; sparse demos interpolate (9 sparse demos cover ≫9× single-demo area), dense central demos do NOT extend range outward (no extrapolation); higher precision shrinks each neighbourhood.
 - Sim one-shot (Table I, max/avg over 3 seeds, averaged over 8 tasks): 1 source 16/13, DemoGen(1 source) 91/88, 10 source 70/68, 25 source 94/91.
 - Real (Table III, source 3 trajectories vs DemoGen): Spatula-Egg 10.0→88.0, Flower-Vase 6.3→82.5, Mug-Rack 6.3→85.0, Dex-Cube 10.0→78.0, Dex-Rollup 8.3→76.7, Dex-Drill 11.1→55.6, Dex-Coffee 11.1→40.0, Fruit-Basket 25.0→90.8; avg 11.0→74.6.
 - Disturbance resistance (Sauce-Spreading, 25 trials, crust shifted twice): normalised score regular DemoGen 40.4 vs DemoGen with ADR (synthetic "object displaced mid-episode, EE re-approaches") 92.3 (human expert 100); coverage 34.2 vs 61.2 (expert 65.2).
 - Obstacle avoidance: synthetic box/cone points + planned detours → 22/25 real trials avoid unseen everyday obstacles.
Ablations:
 - #demos (DP3, full workspace): 100→150 demos +37 pts, 150→200 +6 pts → diminishing returns once workspace covered.
 - Synthetic coverage vs density (Fig 9, Pick-Cube): performance saturates both when widening coverage beyond a threshold (visual mismatch grows with distance from source) and when adding density at fixed coverage — figure only, qualitative.
 - Synthetic < same number of real demos (1-source DemoGen 88 avg < 25 real 91) — single-view "visual mismatch" (object always shows the side seen in the source).
 - Setting proprio state to next action target instead of transformed actual state hurts (stated, no numbers).
 - Replaying the source demo twice to diversify point-cloud noise: stated as needed to avoid overfitting to sensor artefacts (no ablation numbers).
 - ±1.5 cm perturbations added because "policies are sensitive to even small deviations" in placement (no ablation numbers).
Failure/limitations: needs segmentable, uncluttered point clouds; only rigid spatial variation (no appearance, lighting, background variation — point cloud only); visual mismatch grows with displacement/rotation; Dex-Coffee/Drill precision-limited (40–56%); success reported on evaluation grid that equals the generation grid (generation targeted at the eval configs ± 1.5 cm) → optimistic; baseline is only 3 near-identical trajectories, a very weak comparator. Motion segments replanned by a planner → generated trajectories are smoother/different from human style.
Conflicts: Agrees with DataScalingLaws (diversity of configurations/environments > repetitions; diminishing returns per config) and iDP3/DP3 notes (3D gives better spatial generalisation). Its DINOv2/CLIP > R3M > scratch ranking for spatial generalisation disagrees with SPA's frozen-eval ranking (DINOv2 weaker) — different axis (spatial not semantic) and fine-tuned vs frozen. Its absolute-EE-pose + IK choice matches ACT's absolute targets; disagrees with delta preference in ActionSpaceStudy (here absolute needed so generated trajectories execute failure-free).
Relevance: HIGH for the data-collection protocol (not necessarily for the method). (1) Our SO-101 has a RealSense → segmented point cloud is available, but the wrist camera and RGB image branch cannot be synthesised by DemoGen, so direct use requires a point-cloud-only policy. (2) The key transferable lesson: spatial coverage of pumpkin and tray placements, not repetitions, sets the success region; policies do not extrapolate outside the demonstrated placement hull. (3) Joint-space SO-101 actions would need IK to re-target skill segments — feasible (5-DoF arm + gripper, IK approximate) but orientation re-targeting is limited on a 5-DoF wrist. (4) ADR result is direct evidence that recovery behaviour only appears if recovery/disturbance data exists.
Decision impact:
 - Q13 data diversity: spread demos over a grid of object AND target placements covering (slightly beyond) the eval region; do not repeat the same placement — SUPPORTED — confidence H (sim 2025-config sweep + real heatmaps + consistent with other papers).
 - Q13 recovery data: disturbance/recovery demos are required for disturbance resistance (40.4 → 92.3) — SUPPORTED — confidence M (one task, 25 trials, synthetic).
 - Q13 demo count: ~100–150 demos to cover a 40×40 cm config space for a precise task; 50 demos only ~11–17% there; fixed-position tasks need very few — SUPPORTED — confidence M (sim, precise peg; pumpkin pick is lower precision).
 - Q05 augmentation (synthetic demos): point-cloud spatial re-targeting gives large gains when real demos are few (11→75% real) but saturates and stays below equal real data — SUPPORTED as optional add-on for a 3D branch — confidence M.
 - Q04 3D: DP3 ≥ DP+CLIP/DINOv2 ≫ DP scratch for spatial generalisation — SUPPORTED — confidence M.
 - Q03 vision: pretrained DINOv2/CLIP encoders greatly improve spatial generalisation over scratch ResNet (e.g. 100 demos: 61/53 vs 22) — SUPPORTED pretrained init — confidence M; R3M worst (21 at 400).
