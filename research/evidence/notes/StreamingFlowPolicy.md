# StreamingFlowPolicy — Streaming Flow Policy: Simplifying diffusion/flow-matching policies by treating action trajectories as flow trajectories (2025, arXiv 2505.21851, CoRL 2025)
Setup: Flow time = execution time: start from narrow Gaussian around the last executed action (or measured robot state), integrate a learned velocity field v(a,t|h) in ACTION space (not chunk space), streaming each action as soon as it is integrated. Conditional target flow = demo velocity ξ̇(t) + stabilizing term −k(a−ξ(t)). σ0=0 at test time (deterministic). Same DP backbone with I/O changed from A^T to A. Sim: Push-T (200 demos, state & image; 50 eval episodes), RoboMimic Lift/Can/Square (state input, "300 demos", 50 eval episodes); metric = avg of 5 best checkpoints / max (DP protocol). Real: Franka FR3 + RealSense D435f, reach-and-pick apple and block reorientation — QUALITATIVE only (videos), no success numbers. Tpred 16, Tchunk ≈ 8.
Claim: a streaming flow policy keeps DP-level accuracy and multimodality (per-timestep marginals) while cutting per-action latency by ~10× and producing smoother motion because actions start flowing immediately.
Evidence (avg of top-5 checkpoints; latency per action):
 - Push-T state (Table 2), state-imitation / action-imitation: DP-100 DDPM 92.9 / 90.7 (40.2 ms); DP-10 DDIM 87.0 / 81.4 (4.4 ms); conventional Flow-matching policy 80.6 / 80.6 (5.8 ms); Streaming DP 87.5 / 84.2 (26.7 ms); SFP k=0 84.0 / 81.8 (3.5 ms); SFP 95.1 / 91.7 (3.5 ms).
 - Push-T image, state imitation: DP-100 87.0 (127.2 ms); DDIM-10 85.3 (10.4 ms); FM policy 71.0 (12.9 ms); Streaming DP 84.7 (77.7 ms); SFP k=0 73.9 (8.8 ms); SFP 83.9 (8.8 ms). Action imitation (Table 5): DP-100 83.8, DDIM-10 80.8, FM 67.9, Streaming DP 80.5, SFP 82.5.
 - RoboMimic (Table 3) Lift: all ~99–100. Can: DP-100 94.0, DDIM-10 94.8, FM policy 66.0, Streaming DP 96.8, SFP k=0 90.0, SFP 98.4. Square: DP-100 77.2, DDIM-10 76.0, FM 54.0, Streaming DP 77.6, SFP k=0 53.2, SFP 78.0. Latency 53.4 / 5.8 / 4.8 / 30.3 / 4.5 / 4.5 ms per action.
Ablations:
 - Stabilizing gain k=0 → large drop: Square 78.0→53.2, Can 98.4→90.0, Push-T image 83.9→73.9; "insensitive to a wide range of k>0", also insensitive to σ0 and Δt (rebuttal, no table).
 - Feed-forward velocity-field regression (no training noise) vs SFP: Push-T state 82.3 vs 95.1, Push-T action 72.1 vs 91.7, RoboMimic Can 12.4 vs 95.6 → the noise/flow-matching (generative) training is what makes it work (rebuttal numbers).
 - Chunk size (App. C, Fig. 8): figure only, qualitative: peak at chunk 8 in 3/4 envs, 6 in 1/4; drops either side (matches DP "sweet spot").
 - Deterministic σ0=0 at test time works better than the latent-variable stochastic variant (stated, no numbers).
Failure/limitations: authors: matches only per-timestep marginals, not joint trajectory distribution → can splice segments of different demos ("compositional"), cannot capture global trajectory constraints; needs continuous, differentiable actions (binary gripper had to become a continuous open fraction; derivatives by piecewise-linear interpolation). Critical read: sim uses state inputs mostly; image Push-T SFP (83.9) is slightly below DP-100 (87.0) and DDIM-10 (85.3); real-robot claims are video-only; latency advantage per action vs DDIM-10 is small (8.8 vs 10.4 ms) — the real gain is "no wait before first action", i.e. smoothness/reactivity, not throughput. The weak "Flow matching policy" baseline (Can 66, Square 54) contradicts other papers where FM ≈ DP — likely an implementation/hyperparameter issue, so don't read it as "flow matching is worse than diffusion".
Conflicts: DDIM-10 ≈ DDPM-100 here on RoboMimic (94.8 vs 94.0 Can) while ConsistencyPolicy finds DDIM-15 collapses on ToolHang (.14) — step-count sensitivity is task-dependent (precision/long horizon). Starting each chunk from the last action/measured state is conceptually close to RTC/Legato continuity fixes.
Relevance: Attractive for SO-101's jerky chunk boundaries: each new chunk starts exactly at the current (measured) joint state, so no boundary discontinuity; actions stream every few ms. SO-101 leader-follower absolute joint targets are continuous (gripper is a continuous joint on SO-101 — no binary issue). "State imitation" from measured follower joints requires a stiff tracking controller; SO-101 Feetech servos have backlash, so action (leader) imitation is safer. Evidence is sim + qualitative real only; no small-data (50 demo) or robustness data.
Decision impact:
 - Q01 action head: flow-matching-trained velocity field >> deterministic regression of same field (Can 95.6 vs 12.4; Push-T 91.7 vs 72.1) — supports generative/noise-trained heads — confidence M (rebuttal numbers, sim).
 - Q01 action head: streaming flow ≈ DP-100 accuracy (Square 78.0 vs 77.2; Push-T img 83.9 vs 87.0) — supports flow as a DP replacement — confidence M (sim).
 - Q10 latency/smoothness: per-action latency 3.5–8.8 ms vs DP-100 40–127 ms; first action available immediately; chunk starts at last action → removes boundary jumps — supports streaming/continuity-aware flow — confidence M (smoothness only video evidence).
 - Q06 chunking: best execution chunk 6–8 steps (of 16 predicted) — confidence M (sim, consistent with DP).
