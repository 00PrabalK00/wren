# W4_SKILSemanticKeypointImitationLearningfor — SKIL: Semantic Keypoint Imitation Learning for Generalizable Data-efficient Manipulation (2025, arXiv 2501.14400)
Setup: Franka + Robotiq, single fixed third-person ZED2 RGB-D camera; Meta Quest teleop (DROID-style); EE-pose actions. 6 real tasks: 4 short (20 demos), 2 long-horizon (30 demos); trained on 2 objects, tested on 10 unseen same-category objects (short) / 3–5 (long), 5 trials per object. Representation: DiFT (Stable Diffusion 2.1 features) similarity maps vs N (10–30) K-means reference keypoints from a reference image → per-keypoint descriptor [cosine-similarity vector, 3D position from depth] → transformer encoder (mean-pooled) + state → DP-style CNN U-Net diffusion head, DDIM, action chunks. Keypoint-token dropout 20% in training; test-time ensemble of 20 dropout samples, median action. Sim: MetaWorld/DexArt 10 demos.
Claim: sparse semantic keypoint descriptors (semantic similarity + 3D location) give strong object/environment generalization and data efficiency vs DP, DP3, RISE, GenDP.
Evidence (Table I):
 - Train objects avg: DP 36.7, DP3 31.6, RISE 21.7, GenDP-S 36.7, SKIL 81.7.
 - Unseen objects avg: DP 23.0, DP3 25.0, RISE 18.0, GenDP-S 30.0, SKIL 72.8. Per task (unseen): Pick Mouse 4/18/14/32/72; Grasp Handle 36/32/34/32/94; Grasp Wall 36/18/12/30/80; Fold Towel 50/58/32/58/72; Hang Towel 0/0/0/0/72; Hang Cloth 12/24/16/28/47.
 - Environment (Grasp Handle of Cup, /10): Situation 0 (orig) DP 4, DP3 5, RISE 4, GenDP 5, SKIL 9; +distractors 4/1/3/3/9; background color change 0/4/2/5/8; both 0/0/1/2/8. RGB DP collapses under background change; DP3 collapses with distractors.
 - Demo count (train objects): Pick Mouse 10→20 demos SKIL 50→90 vs DP 20→40; Grasp Handle 70→90 vs DP 10→30; Fold Towel 60→90 vs DP 40→60; Hang Towel 20→30 demos 40→70 vs all baselines 0.
 - Human video co-training (SKIL-H, 10 robot + 20 human videos): Pick Mouse +40 pts (figure).
Ablations: vision model (figure, A10 GPU): DINOv2 (all sizes) far behind — severe keypoint mismatches under occlusion; RADIOv2.5-L/H slightly below DiFT at lower latency. Keypoints N=10/20/30: 7–9/10, insensitive. Proposal: K-means 8,7,9 vs manual 7,7,9 vs random 7,6,9 (/10).
Failure/limitations: bounded by foundation-model keypoint precision (bulb assembly failed); only object keypoints → no obstacle awareness. Critical: few trials (5/object), baselines weak on 20 demos (DP 36.7% train) — suggests baselines under-tuned or single third-person cam without wrist cam hurts them; DiFT (Stable Diffusion) feature extraction latency ~100+ ms on A10 (figure).
Conflicts: agrees with ControlVLA, Lan-o3dp, GSL — object-centric/keypoint abstractions beat raw RGB/scene point cloud for novel instances and backgrounds with 10–30 demos. Interesting: DINOv2 bad for dense correspondence keypoints here, while DEM finds fine-tuned DINOv3 best as a global encoder — different uses (frozen correspondence vs fine-tuned features).
Relevance: pumpkin→tray with varied pumpkins is exactly category-level generalization with same structure; semantic keypoints (with RealSense depth for 3D) could fix "different-looking pumpkin" and background/lighting failures. Latency of DiFT is a concern on 8 GB laptop; RADIO-B/L lighter options. Could compute keypoints at lower rate and track.
Decision impact:
 - Q14 robustness: semantic keypoints: unseen objects 72.8% vs ≤30% for DP/DP3/RISE/GenDP; background+distractor 8/10 vs 0–2/10 — supports keypoint/object-centric input — confidence M (real, 6 tasks, but 5 trials/object and weak baselines).
 - Q03 vision encoder: for keypoint correspondence DiFT ≈ RADIO-L/H >> DINOv2 — L/M (figure only).
 - Q04 3D/depth: 3D keypoint positions from depth + semantics > DP3 full point cloud (unseen 72.8 vs 25.0) — M.
 - Q13 data: SKIL at 10 demos > all baselines at 20 — M.
