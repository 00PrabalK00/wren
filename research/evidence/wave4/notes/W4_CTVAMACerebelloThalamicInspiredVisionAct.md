# W4_CTVAMACerebelloThalamicInspiredVisionAct — CT-VAM: A Cerebello-Thalamic-Inspired Vision-Action Model for Efficient Visuomotor Control (2026, arXiv 2606.09572)
Setup: 68M-param policy (35M trainable): DINOv3-S+ backbone, dual view (third-person + wrist) fused patch tokens, proprio history, ONE-HOT task token (no language model in loop), rectified-flow transformer decoder with "TARS" (per-stream softmax attention over self / 32 learnable action queries / dense vision+proprio / task, gated sum). Chunk H=8, 8 flow steps. Sim: LIBERO 4 suites, 50 rollouts/task. Real: OpenArm 7-DoF arm, D435 third-person (640x480) + D405 wrist (424x240), 30 teleop demos/task (PICO 4 VR) recorded at 30 Hz, absolute joint-position targets + gripper, trained batch 32 x 100k steps; control 20 Hz; 20 trials per method-platform; objects randomly placed in reachable workspace. Inference on RTX 4080 and Jetson Orin NX (TensorRT BF16).
Claim: A compact (68M) task-conditioned vision-action policy with stream-separated attention matches billion-scale VLAs, and flow-consistent inpainting (FCI) async execution hides latency with smooth chunk transitions.
Evidence:
 - LIBERO avg (Table 1): OpenVLA 76.5, SpatialVLA 78.1, pi0-FAST 85.5, pi0 86.0 (reported), DP 72.4, MDT 76.1, CT-VAM 82.1 (Long 66.2 vs pi0 73.0).
 - Real Ball Pouring (Table 2, 20 trials, RTX 4080): DP 70% / 27.21 s exec / 303.27 ms inference; pi0 (50 steps) 95% / 7.82 s / 117.24 ms; CT-VAM sync 100% / 8.33 s / 56.32 ms; CT-VAM+FCI 95% / 6.41 s / 56.84 ms. Jetson Orin NX: CT-VAM sync 85% / 10.24 s / 256.24 ms; +FCI 90% / 7.23 s / 200.60 ms; pi0 could not be deployed (memory).
 - Real-time-equivalent rate with FCI (H=8, overlap Kov=4 at 20 Hz = 200 ms hiding window): 20.0 Hz on RTX, 19.94 Hz on Jetson.
Ablations:
 - Action queries (Table 3, LIBERO avg): 4 learnable 73.2; 32 learnable 82.1; 32 fixed 77.2; 64 learnable 73.0.
 - Model size with plain flow-matching head, same encoder, no TARS (Table 4): FM-S 35M/68M 65.8; FM-B 141M/227M 76.9; FM-L 455M/758M 77.3 -> diminishing returns past ~200M; TARS 68M 82.1.
 - FCI vs sync: success 95 vs 100% (RTX), 90 vs 85% (Jetson) — i.e. no success change within 20-trial noise; execution time 8.33 -> 6.41 s and 10.24 -> 7.23 s.
 - FCI vs hard clamp inpainting: argued theoretically (hard clamp gives out-of-distribution intermediate flow states); no numeric comparison.
Failure/limitations: authors: one-hot task IDs, no real language grounding; tabletop only; manual subtask switching in long-horizon task. Critical read: only ONE real task quantitatively compared (Ball Pouring, 20 trials); Box Opening task no baseline numbers; DP baseline is surprisingly slow (303 ms, 27 s) — likely heavy config; no smoothness metric (jerk) reported for FCI; LIBERO baselines are reported numbers; no robustness (lighting/camera) evaluation.
Conflicts: Consistent with RTC / bidirectional-decoding style guided inpainting for async chunking (FCI is essentially RTC-lite with a flow-consistent overlap path, no guidance weights). Model-size scaling (65.8 -> 76.9 -> 77.3) agrees with other small-policy papers that ~100-200M suffices on LIBERO-scale data; differs from VLA scaling narratives. Uses absolute joint targets with 30 demos successfully — contrast with state-free paper's claim that absolute actions kill spatial generalization (here object positions are randomized in training too).
Relevance: Very close to our constraints: two RealSense-type cams (third-person + wrist), 30 demos/task, 30 Hz recording, ~70M model, 56 ms on RTX 4080 (our RTX 5060 laptop likely ~2x slower, ~100 ms — still hideable in a 4-action x 50 ms overlap window). FCI is directly the fix for our async chunk-boundary jerk: keep overlap actions on the flow interpolation path rather than hard clamping. One-hot task token instead of full LM is reasonable for our 1-2 task setting. Frozen/pretrained DINOv3-S+ backbone as encoder.
Decision impact:
 - Q10 latency/async: supports async execution with flow-consistent overlap inpainting (latency fully hidden: 20 Hz effective, exec time -23%/-29%, success unchanged) — M (real robot, but one task, 20 trials, no jerk metric)
 - Q12 model size: supports ~70-230M; plain FM 68M->227M +11 pts, 227M->758M +0.4 pts; 68M structured model beats 758M — M (LIBERO sim)
 - Q06 chunking: H=8 with overlap 4 at 20 Hz works in real — L (not ablated)
 - Q08 language: one-hot task token sufficient for fixed task set, drops LM from control loop — L (no language baseline ablation)
 - Q11 cameras: third-person D435 + wrist D405 dual view used; not ablated — L
 - Q03 vision encoder: DINOv3-S+ pretrained backbone in a 68M policy works with 30 demos — L (not ablated)
