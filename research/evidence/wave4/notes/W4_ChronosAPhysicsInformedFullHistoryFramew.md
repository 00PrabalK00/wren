# W4_ChronosAPhysicsInformedFullHistoryFramew — Chronos: A Physics-Informed Full-History Framework for Non-Markovian Long-Horizon Manipulation (2026, arXiv 2606.30318; T-RO under review)
Setup: 0.3B policy: one fused obs+proprio token per control step -> selective SSM (Mamba) over the FULL episode history -> IMLE coarse multimodal action-chunk prior -> second-order "Schrodinger-inspired" bridge predicting acceleration, integrated 3-5 steps (semi-implicit Euler). Sim: ALOHA insertion (frozen DINOv2 + adapters, 50 demos, 50 trials), 8 RoboTwin 2.0 tasks + 7 RMBench memory tasks (point cloud + PointNet, 50 demos, 100 trials). Real: dual UR3, ONE RealSense D435 RGB view, frozen ResNet18 + adapters (depth deliberately NOT used: D435 cloud too noisy around small objects), 4 tasks x 50 trials; #real demos, control rate and latency not stated. Training on "commodity GPUs" with frozen backbone (no exact compute).
Claim: Treating full observation history as policy state (SSM) + second-order action generation solves memory-dependent tasks and yields smoother motion than Markovian VLAs, at 10-30x fewer params.
Evidence:
 - ALOHA insertion (Table II, same history encoder, 50 trials): ACT 50%, MTIL 76%, Chronos regression head 76%, diffusion head 66%, flow head 72%, IMLE only 86%, regression prior+bridge 84%, first-order schedule 72%, full 90%.
 - RoboTwin 2.0 avg (Table IV, 50 demos, baselines REPORTED not re-run): DP 35.1, ACT 30.6, RDT-1B 35.8, pi0 48.8, DP3 59.5, Chronos 70.0%. Chronos < DP3 only on Put Bottles Dustbin (54 vs 60).
 - RMBench avg (Table V): DP 5.8, ACT 7.4, pi0.5 11.2, X-VLA 11.1, Mem-0 50.8, Chronos 73.6%.
 - Real (Table VI, 50 trials each, pi0.5 vs Chronos): Put Back Blocks 0 vs 98%; Swap T (non-memory control) 28 vs 96%; Swap T-Mem 0 vs 98%; Cover Blocks 0 vs 20%. All 7% vs 78%.
Ablations:
 - Action head (held fixed: encoder, data): diffusion 66 / flow 72 / regression 76 / IMLE 86 / IMLE+2nd-order bridge 90%; replacing quartic bell schedule with first-order diffusion schedule 90 -> 72%.
 - Bridge integration steps N (Table III): 1:84, 2:82, 3:90, 4:84, 5:90, 7:86, 10:84, 15:88% — flat within noise of 50 trials (+-~7 pp), i.e. 1 step already fine.
 - No ablation of history length / Markovian variant of Chronos itself (the memory claim rests on comparisons with other methods).
Failure/limitations: authors: Battery Try (29%) and Press Button (2%) remain unsolved (contact precision, no OCR); real Cover Blocks 20% blamed on frozen ResNet18 losing color-location binding; D435 depth unreliable. pi0.5 real rollouts described as stop-and-go jitter vs Chronos smooth (qualitative only). Critical read: baselines mostly "reported", not re-trained with same encoders; pi0.5 real training recipe/data not described, and pi0.5 28% on the non-memory Swap T suggests a weak baseline setup; ALOHA ablations are 50 trials with differences of 4-10 pp (noise ~+-7 pp). Tasks are purposely aliased (memory-bound) — pick-place of a pumpkin is not.
Conflicts: Contradicts ACT/DP/Diffusion "more history hurts/copycat" findings only superficially — those are Markovian-sufficient tasks; Chronos itself concedes that on fully observable tasks memory is less decisive (DP3 wins Put Bottles). Its diffusion < regression result on ALOHA insertion agrees with ACT-style findings that L1 regression chunks are strong in low data; disagrees with DP paper (diffusion > regression) — likely because of small data (50 demos) and precision insertion. Notable that they, like iDP3, found D435 depth too noisy for small objects.
Relevance: Our pumpkin->tray is Markovian (no aliasing), so full-history memory is not needed; the relevant takeaways are (1) frozen pretrained backbone + small trainable adapters + 0.3B model trains on commodity GPU; (2) D435 point clouds noisy for small objects (pumpkin is large — less of an issue); (3) smoothness from acceleration-level/second-order action parameterization as an alternative remedy for chunk-boundary jerk. If later tasks need phase memory (e.g. "place second object after first"), an SSM over per-step tokens is cheap.
Decision impact:
 - Q01 action head: regression (76) >= flow (72) > diffusion (66) at 50 demos; IMLE+second-order refinement best (90) — L/M (sim, 50 trials, single task)
 - Q07 history/memory: full-history SSM essential only for aliased/memory tasks (real 0 -> 72% on memory tasks); no evidence it helps Markovian pick-place — M for memory tasks, L for ours
 - Q10 smoothness: second-order (acceleration) action generation gives qualitatively smoother real motion than pi0.5; 1-5 integration steps suffice — L (qualitative only)
 - Q04 depth: D435 point clouds judged too noisy for small objects in real, RGB used instead — L
 - Q12 model size: 0.3B with frozen ResNet18/DINOv2 beats 3B+ VLAs on these tasks — L (uncontrolled baselines)
