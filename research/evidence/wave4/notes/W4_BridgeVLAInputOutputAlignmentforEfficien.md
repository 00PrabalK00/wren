# W4_BridgeVLAInputOutputAlignmentforEfficien — BridgeVLA: Input-Output Alignment for Efficient 3D Manipulation Learning with Vision-Language Models (2025, arXiv 2506.07961)
Setup: PaliGemma (SigLIP + Gemma, ~3B) backbone; point cloud from calibrated RGB-D rendered to 3 orthographic views (top/front/right, RVT-style); model outputs per-view 2D heatmaps -> next KEYFRAME EE translation (argmax over 3D grid), rotation as 72-bin Euler classification, gripper + collision flag via MLP; coarse-to-fine zoom second pass; motion planner executes between keyframes. Pre-trained on 120K RoboPoint detection images to output heatmaps. Random rigid-body transforms of point cloud+action as augmentation. Sim: RLBench 18 tasks x 100 demos, 25 trials, 5 seeds; COLOSSEUM (20 tasks, 12 perturbation axes); GemBench. Real: Franka FR3, ONE static ZED 2i depth camera, 13 tasks, 10 demos/task (also 3 demos/task), 10 trials/task. Appendix truncated (training compute not in text).
Claim: keeping 3D inputs and action outputs in the same 2D image space as VLM pre-training (projected views in, heatmaps out) makes a 3D VLA extremely sample-efficient.
Evidence:
 - RLBench avg SR: BridgeVLA 88.2 vs RVT-2 81.4, 3D Diffuser Actor 81.3, Act3D 65.0, PerAct 49.4, Image-BC ~1.3.
 - COLOSSEUM avg: 64.0 vs RVT-2 56.7, RVT 35.4, PerAct 27.9, R3M-MLP 0.8, MVP-MLP 1.6. Per-perturbation BridgeVLA: light color 69.7 (RVT-2 58.0), camera pose 51.8 (RVT-2 64.4 — the one axis where it is NOT best), distractor 74.8, background texture 73.1, all perturbations 18.7 (RVT-2 15.6).
 - GemBench avg 50.0 vs 3D-LOTUS++ 48.0; L4 long-horizon 0.0.
 - Real Basic (10 demos/task, 13 tasks x10 trials): BridgeVLA 96.9%, RVT-2 90%, SpatialVLA(50 demos) 28.5%, ACT 22.3%, pi0 3.8%, SpatialVLA(10) 3.1%. 3 demos/task: 95.4%.
 - Real generalization settings (distractor, lighting-off, background, height, combination, category): figure only, qualitative: BridgeVLA > RVT-2 in all 7, biggest gaps in Lighting and Combination; +32% avg over RVT-2; Category absolute SR "not high".
Ablations (RLBench, all else fixed):
 - heatmap output -> direct position regression with 303M transformer decoder + MSE: 88.2 -> 31.4 (and needed batch 192 + careful LR tuning).
 - adding per-pixel 3D position features (3D conv) into image tokens: 88.2 -> 56.2 (breaks alignment with VLM pretraining).
 - no 2D heatmap pre-training (real): cannot beat RVT-2 on Combination/Category (figure only).
Failure/limitations: keyframe + motion planner formulation (not dense closed-loop control) — the entire comparison vs ACT/pi0 is on a keyframe-friendly task set where 2D dense policies with 10 demos are disadvantaged; baselines like ACT given only 10 demos (ACT normally 50). Place Cups fails due to occlusion in orthographic views; camera-pose perturbation is its worst COLOSSEUM axis; category generalization weak (robot ignores target, goes to destination). Needs calibrated depth camera and a planner/IK — SO-101 has no good motion planner but IK is feasible. Model ~3B; inference latency not reported in main text.
Conflicts: heatmap/spatial-output > regression agrees with RVT/PerAct/Act3D line and with "action-as-pixel" works; contradicts common VLA practice of token/regression heads — but only for keyframe prediction, not for dense trajectories. The "don't inject 3D positions into VLM tokens" result conflicts with SpatialVLA/3D-CAVLA style of adding 3D features to tokens — here adding them hurts by 32 pts because it disturbs a pretrained backbone; 3D-CAVLA adds a separate token instead of modifying image features, which may be the difference.
Relevance: Moderate as a design idea: for pick-pumpkin-place-in-tray (essentially 2–3 keyframes), a keyframe heatmap policy on RealSense point cloud could hit high success with very few demos and is naturally robust to lighting (depth-driven views). But it abandons smooth closed-loop control, requires extrinsic calibration (camera shift breaks it — weakest axis) and a ~3B model; not directly compatible with our 8 GB budget unless using RVT-2-sized non-VLA variant (RVT-2 got 90% real with 10 demos).
Decision impact:
 - Q04 3D/depth: supports 3D point-cloud input (projected views) for data efficiency — 3D methods (RVT-2 90%, BridgeVLA 96.9%) vs 2D (ACT 22%, pi0 4%) at 10 demos — confidence M (real, 13 tasks x10 trials, but keyframe formulation favors 3D)
 - Q01 action head: supports spatial heatmap/classification over direct regression (88.2 vs 31.4) — confidence M (sim, keyframe translation only)
 - Q03 vision encoder: preserve pretrained backbone input distribution; injecting 3D pos features into VLM tokens -> 56.2 vs 88.2 — confidence M (sim)
 - Q13 data quantity: 3 demos/task 95.4% vs 10 demos 96.9% for keyframe 3D policy — confidence M (real, simple pick-place)
 - Q14 robustness: 3D keyframe policy robust to lighting/background/distractor but camera pose is weakest axis (51.8 vs RVT-2 64.4 COLOSSEUM) — confidence M
 - Q11 cameras: single static depth camera sufficient for keyframe policy in real — confidence L
