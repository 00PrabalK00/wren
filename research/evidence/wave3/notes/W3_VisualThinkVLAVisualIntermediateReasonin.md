# W3_VisualThinkVLAVisualIntermediateReasonin — VisualThink-VLA: Visual Intermediate Reasoning for Effective and Low-Latency Vision-Language-Action Policies (2026, arXiv id not in text)
Setup: frozen OpenVLA-7B (also Octo, SmolVLA) + routed adapter consuming up to 4 precomputed "visual evidence" channels (bbox via Grounding DINO/OWL-ViT, edge via SAM2, motion via frame differencing, relation via Qwen2.5-VL; depth/segment screened out). "Benchmarks" = BridgeData V2, Fractal, RoboTurk, LIBERO, UT MUTEX, and a 754.7k-instruction VisualEvidence-Set; success metric on dataset benchmarks is not clearly a closed-loop rollout (likely offline/test-split). Real: PIPER 7-DoF, single fixed external RGB camera, 4 task families x 50 trials, EE actions.
Claim: a sparse, routed set of compact visual cues (bbox/edge/motion/relation) injected as soft tokens improves VLA success while keeping sub-second latency vs textual CoT (ECoT 8.4 s -> 0.37 s).
Evidence:
 - Backbone portability (VisualEvidence-Set test split): OpenVLA 76.26 -> 92.63 (+0.05 s); Octo 49.52 -> 60.39; SmolVLA 42.73 -> 54.68 (latency 0.248 -> 0.352 s).
 - Real (Table 5, 50 trials each; Base / FullSoft / VisualThink): multi-object pick-place w/ distractors 48.6/73.4/75.6; relation placement 45.6/63.7/67.2; contact reorientation 63.4/85.8/83.5; two-stage 26.5/57.4/59.2; completion time 22.7/30.2/25.6 s.
 - Internal: all 6 channels dense ("heavy") -> lower success + higher latency than 4-channel; routed 90.10 vs FullSoft 89.83, 0.395 vs 0.470 s.
Ablations: removing any channel costs 0.7-7.7 pts (BridgeData: bbox/motion/relation most important; LIBERO-Long: edge). Soft-hard routing vs hard masks: LIBERO-Long 85.62 -> 93.82; + distillation 94.87. Depth (Depth Anything V2) and segment channels screened out as low-utility.
Failure/limitations: evidence extraction pipeline (Grounding DINO, SAM2, Qwen2.5-VL) latency is apparently not counted in step latency ("extracted offline"); for real deployment this would be large. Dataset-benchmark "success rates" methodology unclear; real robot 50 trials/family with OpenVLA base but training data/demos for real not stated. Heavy engineering; no robustness to lighting/camera tested explicitly.
Conflicts: Monocular depth channel had little utility (screened out) — mildly consistent with RGB sufficing for these tasks; contrasts with 3D-policy papers where geometry dominates, but here depth is a pooled compact cue, not a point cloud.
Relevance: Mentions SmolVLA directly: object bbox/edge evidence gives +12 pts on their test split at +0.1 s. For us, the cheap transferable piece is an object-detector bbox (pumpkin, tray) token as extra conditioning — object localization cues again help under distractors (real pick-place w/ distractors 48.6 -> 75.6). Full pipeline too heavy for 8 GB and 2 s latency budget.
Decision impact:
 - Q14 robustness: supports explicit object-localization cues (bbox) for distractor robustness — L (real 50 trials but 7B base, evidence cost hidden)
 - Q09 aux/intermediate: supports compact visual intermediates over textual CoT (latency 8.4 s -> 0.37 s) — L
 - Q04 depth: monocular-depth cue screened out as low utility — L
