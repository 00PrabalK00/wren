# W3_GroundedActionModel3DGroundingasaFoundat — Grounded Action Model: 3D Grounding as a Foundation for Robotics (2026, arXiv id not in text)
Setup: Frozen promptable 3D grounding backbone (WildDet3D: 2D box, metric 3D box, predicted metric depth, dense features from a single RGB image; prompts by language/points/boxes) + CoTracker3 to keep object association; policy = MM-DiT (12 blocks) flow-matching head predicting chunks of ABSOLUTE joint-position targets, conditioned on (i) image tokens masked to task objects + robot arm, (ii) detection tokens (object point cloud from predicted depth -> PointNet-style encoder, center w/ Fourier features, extents, 6D rot), (iii) one state-history token (current + previous joints), language via adaLN. Only the action head is trained. Sim: RoboTwin 2.0 50 tasks, single-task, 50 clean demos, 100 rollouts Easy/Hard (backbone first fine-tuned on sim renders with GT boxes/depth); LIBERO-PRO. Real: bimanual YAM (25 demos x 4 target combos, 20 trials ID/OOD), Franka 4 multi-step tasks x 50 demos with Molmo2 planner (20 ID / 10 OOD trials).
Claim: Building the policy on a frozen 3D-grounding foundation (object-centric masked visual tokens + metric object geometry) yields far better robustness to scene randomization and relocated/new targets than VLA/WAM/image/point-cloud policies.
Evidence:
 - RoboTwin 2.0 (Easy/Hard/Avg): DP 28.0/0.6/14.3; ACT 29.7/1.7/15.7; RDT 34.5/13.7/24.1; DP3 55.2/5.0/30.1; pi0 46.5/16.3/31.4; pi0.5 (single-task, theirs) 64.0/25.9/45.0; Spatial Forcing (co-trained) 77.2/26.7/52.0; Abot-M0 57.4/30.4/43.9; FastWAM 77.8/1.9/39.9; GAM 63.0/47.6/55.3 (keeps 76% of clean perf under randomization).
 - LIBERO-PRO avg over 16 settings: GAM 0.61 vs pi0.5 0.53; Pos: Spatial 0.60, Object 0.47 (2-3x best baseline); Task: Spatial 0.88, Object 0.50 vs all baselines <0.11; GAM trails on Obj (appearance/size) e.g. Goal 0.69, LIBERO-10 0.50.
 - Real YAM: ID 19/20 both; OOD visual shift GAM 17/20 vs pi0.5 4/20.
 - Real Franka + planner step completion: ID 64.7 vs pi0.5 42.4 vs MolmoAct2 35.3; OOD 49.8 vs 24.0 vs 17.1 (OOD = background, lighting, object instances, colors, distractors).
Ablations (10 RoboTwin tasks, 20 rollouts, Easy/Hard/Avg):
 - Full 51.5/42.0/46.8; no image masking (full image tokens) 30.5/14.0/22.3; no point cropping (whole-scene points) 18.5/7.0/12.8; neither 17.0/3.5/10.3.
 - Detection tokens only 19.5/12.5/16.0; image tokens only 21.5/19.0/20.3 -> appearance and geometry complementary.
Failure/limitations: grounding errors propagate with no recovery; masking can remove relevant context (unselected obstacles); weaker on object size/appearance changes (grasp adjustments); heavy perception stack (WildDet3D + CoTracker3) — latency/GPU not reported; sim backbone needed domain fine-tuning with GT labels.
Conflicts: DP3 (whole-scene point cloud) 55.2 clean -> 5.0 randomized: "3D input alone does not confer robustness" — contradicts the common claim that point clouds are inherently robust to appearance shift; the robustness comes from object-centric filtering (whole-scene points ablation 12.8 vs 46.8). Agrees with GLUE/GloVLA: object-centric selection is the lever for OOD. Clean-scene SOTA VLAs/WAMs collapse under randomization -> big pretraining without selection doesn't solve visual shift from narrow demos.
Relevance: HIGH. Our failures (lighting, different pumpkin, moved camera) are what object-centric filtering targets. Practical recipe for SO-101: text-prompted detector/segmenter for "pumpkin" and "tray" on the scene cam (+ RealSense depth instead of predicted depth -> real metric point cloud), mask image tokens to objects + arm, crop points to objects, small flow head. Absolute joint targets worked. Caveat: needs calibration for base-frame geometry (moved camera -> recalibrate), and the perception stack may exceed the 8 GB / latency budget unless a lighter detector+tracker is used (e.g., run detection once, track cheaply).
Decision impact:
 - Q14 robustness: object-centric masked image + cropped points: Hard 42.0 vs 3.5 without filtering; real OOD 17/20 vs pi0.5 4/20 — supports object-centric filtering for appearance/distractor shift — confidence M-H (large sim + two real robots, but modest real trials)
 - Q04 3D/depth: whole-scene point cloud (DP3) 55.2 -> 5.0 under randomization; geometry-only tokens 16.0 vs image-only 20.3 vs both 46.8 — supports RGB+object-cropped 3D, weakens raw scene point clouds for robustness — confidence M
 - Q03 vision encoder: frozen task-specific grounding backbone (not VLM) + trained head beats fine-tuned pi0.5 — supports frozen strong perception + small head — confidence M
 - Q01 action head: flow matching over absolute joint chunks (no ablation) — L
 - Q07 history: single state-history token (2 frames) used; no ablation — L
