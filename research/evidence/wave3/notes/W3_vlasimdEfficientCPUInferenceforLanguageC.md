# W3_vlasimdEfficientCPUInferenceforLanguageC — vla.simd: Efficient CPU Inference for Language-Conditioned Manipulation (2026, arXiv id not in text)
Setup: CPU inference engine (SIMD micro-kernels, per-episode caching of instruction features, optional W8A8) benchmarked on Apple M4, i9-14900HX, Ryzen 5 5500, Raspberry Pi 5; six policies with checkpoints trained on 30 Hz SO-101 data: ACT 34M (H=100), DP 278M (H=32, 100-step DDPM or 10-step DDIM), Octo-Small 27M+T5 (H=4), TurboVLA 0.2B (H=12), SmolVLA 450M (H=50), IMPACT 60M + frozen T5-small 35M (H=50). IMPACT = ACT (ResNet-18 ImageNet init shared across 2 views at 480×640 → 600 visual tokens, 6-layer enc / 4-layer dec, CVAE, L1 + KL 10) + cached T5 text tokens + FiLM on ResNet features; ~88 GFLOP/query. Real: SO-101, 44 demos for three instructions in one scene (~15/instruction) + 20 demos drawer task; LeRobot async client; 20 trials/row with Wilson CI; 1 operator, 1 scene. LIBERO: 4 suites, 1 seed.
Claim: CPU deployment of chunked policies is feasible when action supply H/Tq ≥ control rate (lagged) or ≈ 2× control rate (time-aligned, stale actions discarded); a 60M language-conditioned ACT (IMPACT) meets the 30 Hz budget even on a Pi 5, SmolVLA does not.
Evidence:
 - Action supply feff (actions/s, fp32, M4 / i9 / Ryzen / Pi5): ACT 1150/892/627/109; DP-100 7.2/7.2/3.6/0.8; DP-10 58/55/29.3/6.3; Octo-S 76/48/48/7.8; TurboVLA 87/58/57/9.3; SmolVLA 73/42/38/6.1; IMPACT 453/334/262/41.
 - Pi 5 query latency Tq: ACT 0.92 s, DP-100 40.1 s, DP-10 5.08 s, Octo 0.51 s, TurboVLA 1.28 s, SmolVLA 8.19 s, IMPACT 1.21 s. After 90 s soak: IMPACT 33.5 (fp32) / 81.2 (int8) actions/s; ACT 89.9/242.
 - vla.simd vs torch.compile: median 1.4× speedup (0.83–3.37×) over 28 pairs; fp32 fidelity ≤8.8e-5.
 - Transport/serialization added ≈0.5–1.0 s round-trip on top of engine latency for SmolVLA (UR10e); SmolVLA 12/20 on both hosts despite 2× latency difference.
 - SO-101 (20 trials each): IMPACT multi-task tape→box 90%, tape→cup 85%, cup→box 60%; int8 85/95/50; long-horizon drawer 65%. No-language ACT control trained on all three tasks: 20% (9/20 failures from target ambiguity, 7 grasp); single-task ACT specialists 60/90/80% (46/60).
 - LIBERO (no robot pretraining): IMPACT 76.4% mean final checkpoint (Spatial/Object/Goal/Long as 72.4/97.7/87.3/... per table fragments; exact split partly garbled), 78.6% with checkpoint selection. Instruction shuffle on LIBERO-Goal: 91% achieve new instruction, 0% original, vs 88.5% control.
Ablations: runtime settings per CPU (tiled conv +16.9–260%, weight packing +15–31%, threads per view mixed); W8A8 speedup Pi5 2.39–2.68× but slows some policies on M4 (0.66–0.71). No ablation of FiLM vs token path.
Failure/limitations: authors: median latency only (tails matter), one 90 s thermal soak, int8 effect in sim unmeasured, LIBERO 1 seed, SO-101 trials pool servers. Critical read: ACT controls ran synchronously while IMPACT used async, and specialists saw more passes → the language gain is not isolated; grasp-target change (cup→box) is weakest (60%) → language selects destination more easily than object; 20 trials give wide CIs (e.g. 60% = 39–78).
Conflicts: consistent with ACT/BAKU/MT-ACT that FiLM + tokens suffice for multi-task selection with a small ResNet-18 model; contradicts the assumption that VLA-scale language models are needed for a handful of instructions. SmolVLA's own paper reports async deployment feasible on GPU; here on CPUs it needs 0.7–8 s per query, which matches our observed ~2 s on the laptop — suggesting our deployment may effectively be CPU-bound or transport-bound.
Relevance: very high. Same robot (SO-101), 30 Hz data, LeRobot async stack, two cameras at 480×640, ~15–20 demos per instruction. Directly shows a ~60M ACT-style model with cached language + FiLM runs ≥30 actions/s even on a Pi 5 and would be trivially real-time on an RTX 5060; a no-language multi-task ACT collapses (20%) under goal ambiguity → if we add a second object with language, we need explicit language conditioning. Timing formula: need H ≥ 2·d for time-aligned async (d = latency in control steps).
Decision impact:
 - Q10 latency/async: supports small ACT-class model (34–60M): Pi5 0.9–1.2 s, desktop CPU ~0.1–0.2 s per 50–100-action chunk; SmolVLA 450M 0.7–8.2 s on CPU — confidence H (direct measurements, same robot data).
 - Q10 latency/async: use feff = H/Tq ≥ 2·fc for time-aligned async (discard stale actions) — confidence M (analytic, verified on SO-101 only qualitatively).
 - Q12 model size: 60M IMPACT achieves 60–90% on SO-101 multi-instruction with ~15 demos/instruction — supports small models — confidence M (20 trials, single scene).
 - Q08 language: FiLM + cached T5-small tokens enable goal selection (LIBERO shuffle 91% new goal); no-language multi-task ACT 20% vs IMPACT 60–90% — confidence M (confounded by async vs sync and data exposure).
 - Q01 action head: CVAE+L1 chunk regression works on SO-101 at this data scale; DP-100 far too slow on CPU (40 s Pi5) — ~ — M.
 - Q06 chunking: long chunks (H=50–100 at 30 Hz, 1.7–3.3 s) needed to cover CPU latency; Octo H=4 fails budget regardless of speed — confidence M.
