# W3_MemERScalingUpMemoryforRobotControlviaEx — MemER: Scaling Up Memory for Robot Control via Experience Retrieval (2025, arXiv 2510.20328)
Setup: DROID-style Franka, third-person ZED + wrist miniZED at 320x180 (15 Hz, subsampled to 2 Hz for policy). Hierarchical: Qwen2.5-VL-7B high-level (~1 Hz) outputs a language subtask + keyframes to remember (<=8 selected keyframes, 1D clustering filter). Low-level pi0.5-DROID fine-tuned (15-action chunks at 15 Hz, execute 8, ~2 Hz). 50 long-horizon demos + 10–15 intervention demos per task, 3 memory tasks (object search, counting scoops, dust & replace), 20 trials each. Training 96 + 48 H200 GPU-hours. Policies run asynchronously on separate servers.
Claim: selecting and keeping task-relevant keyframes beats no/short/long raw history for minute-scale memory tasks.
Evidence: MemER >90% on all three tasks and on par with the human high-level oracle. Long History (32 frames, ~16 s) averages 34% worse than MemER and costs ~1 s inference. No-history and 8-frame history do poorly (Fig. 5; Table 1 raw counts garbled in extraction). GPT-5 and Gemini-Robotics-ER as high-level fail in closed loop because of 10–15 s API latency. Images-only memory beats text or text+image memory (figure). Model merging (0.8 fine-tuned + 0.2 pretrained VLM weights) helps or maintains all tasks.
Ablations: history type/length as above. Multi-task vs single-task high-level: multi-task generalizes better to object combinations (appendix).
Failure/limitations: main failures come from the low-level policy. Compute is far beyond ours (7B + pi0.5). Tasks are chosen to require memory.
Conflicts: agrees with copycat/causal-confusion literature that naive long history is brittle and costly. Memory is kept in the high level, while the low-level control policy stays Markovian (single current frame + state).
Relevance: low for a single pick-place, which is Markovian. Useful points: (1) a Markovian low-level policy is the default even in memory-heavy systems; (2) 10–15 intervention demos starting from observed failure states are a standard robustness patch; (3) the async execution pattern (execute 8 of 15 at 15 Hz while the next chunk is computed).
Decision impact:
 - Q07 observation history: - raw long history at the low level; keep low-level Markovian and add explicit memory only if the task requires it (32-frame history costs 1 s and is 34% worse than keyframe memory) — confidence M
 - Q13 data: + add 10–15 intervention/recovery demos from observed failure states — confidence L (not ablated)
 - Q10 latency: ~ async high/low-level servers and 8-of-15 chunk execution used for smoothness — confidence L (not ablated)
