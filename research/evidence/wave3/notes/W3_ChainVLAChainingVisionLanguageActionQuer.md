# W3_ChainVLAChainingVisionLanguageActionQuer — ChainVLA: Chaining VLA Queries through a Unified Execution State for Long-Horizon Manipulation (2026, arXiv 2608.02326)
Setup: sim only — RMBench (5 memory-dependent bimanual tasks, 100 episodes/task) and LIBERO 4 suites (50 eps/task). 1.2B params: Florence-2-large backbone + conditional flow DiT decoder; 50 demos/task, 20k steps, batch 4, 4x L20; horizon H=30, execute 24 (6-step unexecuted "Motion Tail"); single seed. Two carried states: Progress Context (recurrent working tokens + sparse event memory, stage-supervised writes) and Motion Tail (previous chunk's unexecuted suffix used both as tokens and as the mean of the flow initialization, plus 0.2-weight overlap-consistency loss, tail used with p=0.5 in training).
Claim: carrying both task progress and the previous plan's unexecuted continuation across chunk queries is needed for long-horizon memory tasks; post-hoc smoothing cannot substitute.
Evidence (Table 1): RMBench avg 62.8 vs Mem-0 (8B+2B) 52.8, π0.5 11.8, X-VLA 9.0, MemoryVLA 19.6, DP 6.4, ACT 2.0. LIBERO avg 98.8 (Long 98.2) — near ceiling, not discriminative.
Ablations (Table 2, RMBench avg, 100 eps/task, matched protocol):
 - Full 62.8; w/o Motion Tail 11.2; w/o Progress Context 3.0; w/o both 1.6.
 - w/o tail tokens 52.0; w/o tail-aligned trajectory init 38.0 (initializing the flow from the previous suffix is the more important route).
 - w/o live tokens 47.2; w/o event readout 32.2 (Put Back Block 96 → 25); periodic writes without stage annotation 53.4.
 - Substitute "FIFO observation history + temporal ensembling" 35.6 (−27.2 vs Full).
 - Post-decoding controls (Table 3/A5): Put Back Block success Full 96 vs Linear Continuation 0 vs Temporal Ensemble 0 vs no-tail 0; Swap Blocks 74 vs 2 / 0 / 2. Linear continuation had the LOWEST seam discontinuity (CDp 2.09 mm vs Full 2.69) yet 0% success → smooth seams ≠ success.
 - Boundary metrics Full vs no-tail (80 matched pairs): position discontinuity 7.51 → 3.26 mm (−56.6%), orientation −40.4%, boundary 2nd difference −57.4%, overlap RMSE −43.1%.
Failure/limitations: authors: sim only, fixed control rate, no async/real-time evaluation, single seed, ablations remove pathways from training+deployment jointly (system dependence, not mechanism); external baselines not re-run. My read: RMBench tasks are designed to be memory-dependent (history-aliased), so the huge ablation gaps are specific to that regime; our pick-place is mostly Markovian.
Conflicts: contradicts ACT's view of temporal ensembling as a free improvement — here TE gives 0% on memory tasks (TE blends plans but can't carry state; also averages across modes). Agrees with RTC / Training-RTC / ACNet that conditioning generation on the previous chunk's committed/unexecuted actions is better than post-hoc blending. Supports history for aliased tasks (like SeedPolicy), not naive frame stacking.
Relevance: moderate. Actionable idea for our jerky chunk boundaries: initialize the flow/diffusion sampling from the previous chunk's unexecuted suffix (+noise) and add an overlap-consistency loss — cheap, compatible with a small flow head. Memory machinery is overkill for single-stage pumpkin pick-place; 1.2B too large for our latency budget but the tail trick is model-agnostic.
Decision impact:
 - Q10 smoothness/async: supports conditioning next chunk on previous unexecuted suffix (seam discontinuity −57%; no-tail 11.2 vs 62.8) over temporal ensembling/linear blending (0% on two tasks) — confidence M (sim, single seed, but matched ablations with 100 eps).
 - Q06 chunking/TE: weakens temporal ensembling as smoothing fix for multimodal/long-horizon tasks — confidence M.
 - Q07 history: supports carried recurrent state + sparse event memory over FIFO frame history (35.6 vs 62.8) for aliased tasks — confidence M (only matters for non-Markovian tasks).
 - Q01 action head: flow-matching head enables prior-initialized sampling (tail-aligned init is the load-bearing route, 38.0 without) — confidence L.
