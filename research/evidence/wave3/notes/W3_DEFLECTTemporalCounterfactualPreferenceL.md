# W3_DEFLECTTemporalCounterfactualPreferenceL — DEFLECT: Temporal Counterfactual Preference Learning for Delay-Robust Asynchronous VLAs (2026, arXiv n/a in text)
Setup: offline post-training (flow-matching DPO + SFT anchor) of async VLAs. Frozen reference VLA generates a "preferred" chunk from the execution-time observation (t+d) and a "rejected" chunk from the stale one (t); the trained policy scores both under the deployable input (stale image o_t + future robot state s_{t+d}, VLASH-style). Kinetix (12 tasks × 1,024 rollouts, chunk 8, delays d=0–7, trained d=0–4), LIBERO with pi0.5 (500 eps/suite/delay), real bimanual arm: 3 dynamic tasks (conveyor ×2, whack-a-mole), 30 trials/cell, pi0.5 vs VLASH vs DEFLECT. d=5–7 at 30 Hz ≈ 167–233 ms latency.
Claim: async execution creates a prediction–execution mismatch; training the policy to prefer execution-time-aligned chunks extends the usable delay envelope with no inference cost.
Evidence:
 - Kinetix (Table 1, avg d=0–7 / avg d=5–7): Naive 42.4 / 1.5; RTC 48.9 / 2.0; BID 46.7 / 2.0; PFM 78.4 / 65.5; VLASH 79.4 / 67.1; DEFLECT 83.3 / 73.5. With chunk 8 and d≥5, only 1–3 overlap actions remain → RTC/BID inpainting schedulers collapse (≤5%).
 - LIBERO pi0.5: DEFLECT ≥ VLASH at every delay; +4.6 ±2.7 pts at d=7 (2,000 eps).
 - Real (30 trials): Conveyor-I pi0.5 76.7%, VLASH 86.7%, DEFLECT 96.7%; Conveyor-II 46.7 / 83.3 / 90.0%; Whack-a-Mole moles/30 s 8.9 / 10.4 / 13.6.
Ablations: no SFT anchor → 12.3 avg (−71 pts); scoring A+ and A− under their own observations instead of the shared deployable input → worse at all delays (−0.3 to −2.3); delay-unaware preference (PFM) hurts vs VLASH at d≥2; trained only on d∈{1,2} still +3.7 over VLASH at d=7; after removing cosine-restart artifact gains are +1.6/+2.3/+2.0 at d=5/6/7.
Failure/limitations: little benefit at low delay (fresh ≈ stale); only flow-matching heads tested; tasks chosen to be dynamic (moving conveyor) — in quasi-static pick-place the stale-observation problem is much weaker. Most of the gain over naive async comes from VLASH (conditioning on the future robot state), not DEFLECT itself.
Conflicts: shows RTC/BID-style inpainting need enough overlap (chunk length minus delay); consistent with RTC paper's own assumption. Suggests that when delay approaches chunk length, state-forwarding (VLASH) is the key fix, not smoothing.
Relevance: moderate-high for our async jerk problem: with ~2 s SmolVLA latency, delay would exceed any reasonable chunk → both RTC and naive async break; the first fix is cutting latency (smaller model) so that delay ≪ chunk length, then feeding the robot state at execution start (s_{t+d}) as proprio input. Our pumpkin task is static, so preference post-training is low priority.
Decision impact:
 - Q10 latency/async: when delay leaves only 1–3 overlapping actions, naive async, RTC and BID collapse (1.5–2.0% vs 42–49% avg); conditioning on the future robot state (VLASH) keeps 67% — supports (a) keeping delay well below chunk length and (b) state-forwarding in async — confidence M-H (large sim N + real).
 - Q06 chunking: overlap budget = chunk length − delay must be ≥ several steps for inpainting-based smoothing — supports longer chunks when async — confidence M.
