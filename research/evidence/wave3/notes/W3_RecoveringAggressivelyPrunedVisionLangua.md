# W3_RecoveringAggressivelyPrunedVisionLangua — Recovering Aggressively Pruned Vision-Language-Action Models with Offline Hidden-State Distillation (2026, arXiv 2609.19579)
Setup: Width-prune (heads + MLP channels, residual width kept) the Llama-2-7B backbone of OpenVLA-OFT (L1 chunk head) and CogACT (diffusion transformer head); action-loss Taylor importance; recover offline with LoRA r=32 + hidden-state MSE distillation to a cached teacher (~8 H100 GPU-h). Sim: LIBERO-Long (500 ep), SimplerEnv Google-Robot (864 ep), LIBERO-Plus; 3 seeds, paired McNemar tests. Real: AgileX PiPER 6-DoF, 450 demos over 10 tasks, 20 trials x 10 tasks, on-board Jetson Thor.
Claim: aggressively pruned VLAs (up to ~72-85% backbone reduction) can be recovered offline to near-teacher success; hidden-state KD matters beyond ~45-63% reduction.
Evidence:
 - OpenVLA-OFT LIBERO-Long: no recovery 89.2 (27%) / 54.4 (45%) / 0.8 (63%) / 0 (72%); SFT+KD 91.9 / 90.0 / 89.7 / 90.1; teacher 93.2. SFT-only 90.2 / 89.9 / 87.6 / 87.9.
 - CogACT SimplerEnv: teacher 67.2; SFT+KD 75.2 / 74.9 / 71.9 / 68.6 / 56.2 at 27/45/63/72/81%; SFT-only 75.8 / 72.0 / 61.6 / 46.5 / 36.6.
 - Real PiPER at 72% reduction: teacher 65.5%, SFT student 59.5%, SFT+KD student 77.5% (200 paired eps); long-horizon family 56.7 / 43.3 / 68.3. On-board latency 362 ms -> 162 ms (2.23x), memory 15.0 -> 5.7 GiB.
 - Workstation latency: OpenVLA-OFT 59.3 ms teacher -> ~50-52 ms (width pruning barely helps on H100); CogACT 129 -> 85 ms then floor (10 DDIM steps fixed cost). Memory scales with params (15.9 -> 5.6-6.8 GiB).
Ablations: pruning criterion at 45% before recovery: action-Taylor 54.4, CE-token 50.2, magnitude/random 0; after recovery equal in-distribution (~87-90) but differ on LIBERO-Plus (63.4 vs 58.6 vs 50.1). Width vs depth pruning: width +2.8 to +12.9 (OFT) and +9.0 to +33.2 (CogACT) success; depth 1.31-1.66x faster vs 1.14-1.18x. LoRA ~ full FT. Tripled budget at 81% closes gap 14.3 -> 3.9 pts.
Failure/limitations: sweeps sim-only; one VLM family; unaugmented caches. Critical read: the student beating its teacher on real is likely due to extra recovery training (20k steps with GT actions) rather than pruning; 5.7 GiB at 72% prune still large for an 8 GB laptop with activations.
Conflicts: Aligns with Anchor-Align (keeping representation close to a teacher preserves robustness). Shows backbone params dominate memory but not latency — denoising steps and layer count set latency floors, consistent with SmolVLA/latency literature.
Relevance: For our ~2 s SmolVLA latency: parameter pruning alone gives modest GPU speedups (1.14-1.5x); layer (depth) removal and fewer denoising steps matter more for latency; distillation to the original model is needed to keep robustness. Probably simpler for us to train a small policy (ACT/DP-sized) than to prune a VLA.
Decision impact:
 - Q10 latency: depth (layer count) and fixed denoising steps set latency floors; width pruning 72% gives only 1.16x on H100 (2.23x on Jetson) — confidence M.
 - Q12 model size: 7B backbone can lose ~72% of params with near-teacher success when distilled (real 77.5 vs 65.5), suggesting large VLA backbones are heavily over-parameterized for task-specific finetuning — M.
 - Q14 robustness: action-aware pruning + hidden-state KD preserves OOD robustness (LIBERO-Plus 63.4 vs 65.2 teacher; SimplerEnv variants 60.7 KD vs 37.2 SFT) — M.
