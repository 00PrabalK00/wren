# VLASH — Real-Time VLAs via Future-State-Aware Asynchronous Inference (2025, arXiv 2512.01031, MIT/NVIDIA; code github.com/mit-han-lab/vlash)
Setup: Sim: Kinetix (RTC setup: MLP-Mixer flow policy H=8, 12 tasks × 1,024 rollouts, delays 0–4) and LIBERO (π0.5 and SmolVLA fine-tuned 30K it, bs 32, K=5, delays 0–3). Real: π0.5 and GR00T N1.6 on Galaxea R1 Lite AND LeRobot SO-101; pick&place / stacking / sorting (SmolVLA protocol), K=24 at 30 Hz, laptop RTX 5090, inference delay 2 steps, 20 rollouts × up to 3 attempts per method. Dynamic tasks: ping-pong (20 serves), whack-a-mole (5 rounds).
Method: (1) At inference, feed the CURRENT image plus the robot state ROLLED FORWARD through the Δ still-to-execute actions of the previous chunk (absolute actions: last queued action = estimated state; delta: sum). (2) Fine-tuning augmentation: sample offset δ∈{0..Δmax}, train on (o_t, s_{t+δ}) → a_{t+δ:t+δ+H−1}; same image, shifted state/action — forces the model to actually use proprio. Shared-observation packing (one image encoding, several offset branches via attention mask) gives 3.26× faster per training step. Deploy with the smallest δ ≥ measured Δ. (3) Optional "action quantization": resample q consecutive actions into one macro-action for ~q× faster execution. No architecture change, no inference overhead.
Evidence:
 - Kinetix: at delay 4, VLASH 81.7% vs naive async 51.2%; RTC "degrades rapidly" with delay (figure only).
 - LIBERO π0.5 avg SR: Sync (d=0) 96.8; VLASH d=1/2/3: 97.2 / 97.1 / 94.6. SmolVLA: Sync 79.0; VLASH d=1/2/3: 77.1 / 78.1 / 79.1. (No naive-async numbers in this table — authors say async methods behave similarly on slow LIBERO.)
 - Max reaction latency, π0.5, K=25 @50 Hz (H100 / RTX 5090): Sync 546.4 / 558.8 ms; RTC 96.8 / 99.2 ms; VLASH 46.4 / 58.8 ms. Model latency 23.2 ms (Sync/VLASH) vs 48.4 ms (RTC) on H100 — RTC's guidance roughly doubles latency.
 - Real (Fig. 7/8, figure only): VLASH highest SR on all 3 tasks for π0.5 and GR00T; on pick&place and sorting VLASH at q=2 ≥ Sync at q=1 (2× speed with no loss); stacking needs q≤1.5.
 - Dynamic (Table III, q=2): ping-pong hit rate Sync 0/20, naive async 0/20, RTC 0/20, VLASH 11/20; whack-a-mole score 3.2 / 8.6 / 11.0 / 28.8.
 - Fine-tuning efficiency: offset augmentation converges slower early but reaches the same LIBERO SR by 30K steps; does not hurt sync performance.
Ablations: no ablation of "future state at test time without the offset fine-tuning" in numbers — authors only state that VLAs under-use state and naive test-time substitution is insufficient.
Failure/limitations: future image is unknown (only proprio is forwarded); real SR numbers figure-only; real-task per-method trials = 20 rollouts; state roll-forward assumes the robot tracks commanded actions (absolute targets → last command). Critical read: on a backlash-prone Feetech arm, "last commanded position" ≠ actual position; the paper tested SO-101, but with π0.5/GR00T, not SmolVLA, on the real arm.
Conflicts: argues RTC's inference overhead widens the delay and hurts (contrasts RTC's claim of robustness); DEFLECT (Kinetix) independently finds VLASH 79.4 vs RTC 48.9 avg over d=0–7. LIBERO results show async ≈ sync, so gains appear only where the world or robot moves during inference.
Relevance: HIGHEST practical relevance: SO-101 + SmolVLA are both in the paper; the change is ~a data-loader offset + feeding the last queued action as state; zero inference cost; compatible with any head (flow or L1).
Decision impact:
 - Q10 async: condition on rolled-forward state + train with random state/action offsets — SUPPORTED — M/H (sim large-N, real SO-101 but figure-only).
 - Q10 latency: avoid inference-time guidance (RTC) when latency is already the bottleneck — M.
 - Q10 speed: action resampling q=1.5–2 gives ~1.5–2× faster task completion without loss on pick-place — M (figure only).
